STEP 01
🗂️
git init — Start Your Project
Initialize Local One-time setup

Purpose: Tell Git to start watching your folder

Command
git init

Makes a hidden .git folder inside your project. Git uses this to remember every change you make.

Example
mkdir my-app        ← create a new folder
cd my-app           ← go inside it
git init            ← tell Git to watch this folder
Workflow
📂 Empty Folder │ │ git init ▼ 📂 my-app/ └── .git/ ← Git is now watching ✅
⚠ Common Error
fatal: not a git repository
✅ Fix: You forgot git init — run it first!
Steps
1
Open terminal → go to your project folder
2
git init
Git starts watching ✅
STEP 02
🔍
git status — Check What's Going On
Check Always Run

Purpose: Always run this to know what's happening in your project

Command
git status

Shows you a report — which files are changed, which are staged, which are new.

Example Output
Untracked files:
  ❓ index.html     ← new file, Git doesn't know it yet

Changes not staged:
  ❌ style.css      ← changed but NOT staged yet

Changes to be committed:
  ✅ app.js         ← staged, ready to commit
Workflow
📁 Your files ├── ✅ Staged → ready for git commit ├── ❌ Modified → needs git add └── ❓ Untracked → new file, needs git add
💡 No error! If you see nothing to commit, working tree clean — that just means everything is saved. ✅
STEP 03
➕
git add — Pick Files to Save
Stage Local

Purpose: Choose which files go into your next save. Moves files to the "waiting room" (staging area).

Commands
git add filename.txt   ← add one file
git add .              ← add ALL changed files ✅
Workflow
📁 Working Folder 📋 Staging Area (waiting room) index.html ──────────────────▶ index.html ✅ style.css ──────────────────▶ style.css ✅ app.js (not added yet) ❌ git add . ← adds everything at once
⚠ Common Error
nothing to commit, working tree clean
✅ Fix: You haven't changed any files yet — edit something and save it first!
1
Make and save your changes in the editor
2
git add .
Move all changes to staging ✅
STEP 04
💾
git commit — Save a Snapshot
Save History Snapshot

Purpose: Create a save point with a description of what you did. Like taking a photo of your project.

Command
git commit -m "your message here"
Example
git commit -m "Add homepage design"
Workflow
📋 Staging Area 💾 Local History (Commits) index.html ──────────▶ ● Commit #3: "Add homepage" style.css ──────────▶ ● Commit #2: "Fix button" ● Commit #1: "First save"
● Commit #3 ← newest (where you are now) │ ● Commit #2 │ ● Commit #1 ← oldest (first save)
⚠ Common Error
Please tell me who you are
✅ Fix: Run these once:
git config --global user.name "Your Name"
git config --global user.email "you@email.com"
1
git add .
Stage your files
2
git commit -m "message"
Describe what you did clearly ✅
STEP 05
🔗
git remote add — Connect to GitHub
Remote One-time setup

Purpose: Link your computer project to GitHub. Do this only ONCE per project. origin is just a nickname for the GitHub link.

Command
git remote add origin https://github.com/username/repo-name.git
Workflow
💻 Your Computer ☁️ GitHub 📂 my-app/ 📁 username/repo-name │ │ └──────── connected ───────────┘ (origin) git remote add origin <url>
⚠ Common Error
error: remote origin already exists
✅ Fix: Connection already set! Skip this step and go to git push.
1
Create a repo on GitHub
Click "New Repository" on GitHub
2
Copy the repo URL from GitHub
3
git remote add origin <url>
Run only once ✅
STEP 06
🚀
git push — Upload to GitHub
Upload Remote GitHub

Purpose: Send your saved work to GitHub. Uploads your commits from your computer to GitHub.

Commands
git push -u origin main    ← first time only
git push                   ← every time after ✅
Workflow
💾 Your Computer ☁️ GitHub Commit #3 ─────────────────▶ Commit #3 ✅ Commit #2 ─────────────────▶ Commit #2 ✅ Commit #1 ─────────────────▶ Commit #1 ✅ git push origin main
⚠ Common Error #1
error: src refspec main does not match any
✅ Fix: No commits yet OR branch is "master" not "main". Run:
git branch -M main
git push -u origin main
⚠ Common Error #2
rejected — non-fast-forward
✅ Fix: GitHub has newer changes. Run git pull first, then push.
1
Make sure you have at least one commit
git add . && git commit -m "message"
2
git push origin main
Files appear on GitHub ✅
🔁
Repeat This Every Time You Make Changes

After your first push, just repeat these 3 commands forever:

✏️
Edit your files
Make changes in your editor
↓
📋
git add .
Stage all changes
↓
💾
git commit -m "what I changed"
Save a snapshot
↓
🚀
git push
Upload to GitHub
↓
✅
GitHub is updated!
STEP 07
⬇️
git pull — Get New Changes from GitHub
Download Sync

Purpose: Get updates others have pushed — always do this before starting work. Downloads new commits from GitHub and merges them into your local project. = git fetch + git merge in one step.

Command
git pull origin main
Workflow
☁️ GitHub 💻 Your Computer Commit #4 ─────────────────▶ Commit #4 ✅ new! Commit #3 Commit #3 Commit #2 Commit #2 Commit #1 Commit #1 git pull origin main
⚠ Merge Conflict Error
CONFLICT (content): Merge conflict in index.html
✅ Fix: Two people edited the same file. Open it and look for:
<<<<<<< HEAD
your version
=======
their version
>>>>>>> origin/main
Delete the markers, keep the right code, then:
git add .
git commit -m "fixed conflict"
☀️Run git pull every morning before you start working!
STEP 08
🌿
git branch — Create a New Branch
Branch Safe Work

Purpose: Work on a new feature without touching the main project.

💡 main branch = your ORIGINAL project (don't touch this!)    new branch = a PHOTOCOPY where you freely try new things
Commands
git branch                    ← see all branches
git branch feature-name       ← create a new branch
git branch -d feature-name    ← delete a branch
Workflow
Before: main ●──────●──────● ↑ you are here After: git branch add-login main ●──────●──────● \ add-login ● ← new branch created here
⚠️This only CREATES the branch. You are still on main! You must use git switch to actually go into it.
⚠ Common Error
error: branch already exists
✅ Fix: That name is taken. Choose a different name.
STEP 8b
🔀
git switch — Jump Into a Branch
Switch Navigate

Purpose: After creating a branch, jump into it to start working there.

Commands
git switch feature-name       ← move into that branch
git switch main               ← go back to main
Workflow
Before switch: main ●──────●──────● ← you are HERE \ add-login ● After: git switch add-login main ●──────●──────● \ add-login ● ← now you are HERE ✅
Branch Tree
🌳 main ← official working version (safe!) │ ├── 🌿 add-login ← you switched here, working now ├── 🌿 fix-bug ← another branch waiting └── 🌿 new-design ← another experiment
🧠
git branch add-login
→ MAKE a copy 📋
git switch add-login
→ JUMP into it 🏃
⚠ Common Error
error: pathspec 'feature-name' did not match any file
✅ Fix: Run git branch feature-name first to create it!
STEP 09
🔗
git merge — Bring Your Work Back to Main
Merge Combine

Purpose: When your feature is ready, join it back into main. You wrote on the photocopy (branch) → now you paste it back into the original (main).

Commands
git switch main           ← go back to main FIRST
git merge feature-name    ← pull your feature into main
Workflow
Before merge: main ●──────●──────● \ add-login ●──────●──────● A B C After: git merge add-login main ●──────●──────●──────●──────●──────● ✅ A B C ↑ add-login work is now in main!
⚠ Merge Conflict
Merge conflict in style.css
✅ Fix: Open the file, look for <<<<<<< markers, keep correct code, then:
git add style.css
git commit -m "resolve conflict"
🧠
git branch add-login → MAKE a copy 📋
git switch add-login → JUMP into it 🏃
git merge add-login → BRING it back ✅
1
git switch main
Go to main first
2
git merge feature-name
Your feature is now part of main ✅
3
git branch -d feature-name
Clean up: delete the branch
STEP 10
📜
git log — See All Your Saves
History View

Purpose: See every save you've made — when, by who, and what message. Shows every commit in order — newest at top.

Commands
git log              ← full details
git log --oneline    ← short and clean ✅
Example Output
a3f91bc  Add login page        ← newest
7d82ec1  Fix button color
3b1c209  Add homepage design
f0e1234  First save            ← oldest
Workflow
● a3f91bc "Add login page" ← HEAD (you are here now) │ ● 7d82ec1 "Fix button color" │ ● 3b1c209 "Add homepage design" │ ● f0e1234 "First save"
⚠ Stuck in log screen?
✅ Press q to quit
STEP 11
↩️
git revert — Undo a Mistake
Undo Safe Dangerous

Two ways to undo — choose wisely:

✅ revert — SAFE
Safely undo one commit. Keeps full history. Recommended.
⚠️ reset — DANGEROUS
Go back hard, deletes history. Be careful!
Commands
git revert <commit-id>       ← safe undo
git reset --hard HEAD~1      ← undo last commit (dangerous!)
Example
git log --oneline
# a3f91bc  Add login page  ← has a bug!

git revert a3f91bc    ← safely undo just this commit
Workflow
Safe undo (revert) ✅ Before: ●──────●──────●(bad) After: ●──────●──────●(bad)──────●(undo) ↑ history kept! Dangerous undo (reset) ⚠️ Before: ●──────●──────●(bad) After: ●──────● ← bad commit GONE forever
⚠ Common Error
Cannot revert a merge commit
✅ Fix: git revert -m 1 <commit-id>
1
git log --oneline
Find the commit ID
2
git revert <id>
Undo safely ✅
STEP 12
🗑️
git rm — Delete Files
Delete File Management

Purpose: Delete a file from your project and tell Git about it.

Commands
git rm filename.txt              ← delete the file
git commit -m "removed file"     ← save the deletion
git push                         ← update GitHub
Example
git rm demo123.txt
git commit -m "deleted demo123.txt"
git push origin main
Workflow
📁 Your Project ├── README.md ← stays ✅ └── demo123.txt ← you want to delete this │ │ git rm demo123.txt ▼ deleted from folder │ │ git commit -m "removed" ▼ deletion saved │ │ git push ▼ removed from GitHub ✅
Delete on GitHub (Easiest Way)
1. Open your repo on GitHub
2. Click on the file
3. Click the 🗑️ trash icon (top right)
4. Click "Commit changes"
Done! ✅
Comparison
CommandWhat happens
git rm file.txtDeletes file AND tells Git ✅
rm file.txtOnly deletes locally, Git still sees it ❌
⚠ Common Mistake
Using rm instead of git rm → Git won't know about the deletion!
✅ Always use git rm so Git knows about it!
STEP 13
🔗
GitHub — Clone, Fork & Pull Request
Clone Fork Pull Request
📥 git clone — Copy a Project from GitHub

Purpose: Download someone's project to your computer. Downloads the full project with all history.

git clone https://github.com/username/repo-name.git
Workflow
☁️ GitHub Repo https://github.com/user/project │ │ git clone <url> ▼ 💻 Your Computer 📂 project/ ← full copy is here ✅
🍴 Fork & Pull Request — Contribute to Others

Fork = your own copy of someone's GitHub project
Pull Request (PR) = asking them to include your changes

Full Example
# 1. Fork on GitHub (click Fork button)
# 2. Clone your fork
git clone https://github.com/your-username/forked-project.git

# 3. Create a branch
git branch my-fix
git switch my-fix

# 4. Make changes then save
git add .
git commit -m "Fix the broken link"

# 5. Push to your GitHub
git push origin my-fix

# 6. Open Pull Request on GitHub website
Workflow
Original Repo (owner) ☁️ github.com/owner/project │ │ Fork (click on GitHub) ▼ Your Fork (your copy) ☁️ github.com/you/project │ │ git clone ▼ 💻 Your Computer │ make changes │ git push ▼ ☁️ Your Fork (updated) │ │ Pull Request ▼ Original Repo ← owner reviews & merges ✅

🚨 Quick Error Fix Guide
Error What It Means Fix
fatal: not a git repository Not inside a Git folder Run git init or go to correct folder
nothing to commit No changes made Edit a file first
CONFLICT Two people edited same line Fix <<<<<<< markers → git add → git commit
rejected — non-fast-forward GitHub is ahead of you Run git pull first then git push
src refspec main does not match No commits yet or wrong branch name git add . → git commit → git push
Please tell me who you are Git needs your name git config --global user.name "Name"
Stuck in log view Inside git log screen Press q to exit
remote origin already exists Already connected to GitHub Skip git remote add, just git push
